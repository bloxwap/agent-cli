The npm package ships `SKILL.md` and embeds the same content in the CLI. Install it with:

```sh
agent-cli skill install --target codex
agent-cli skill install --target claude
```

Codex uses `$CODEX_HOME/skills/agent-cli/SKILL.md` (default `~/.codex/skills/agent-cli/SKILL.md`). Claude Code uses `~/.claude/skills/agent-cli/SKILL.md`. Reinstalling identical content is idempotent; replacing edited content requires `--force`.

The following guide comes directly from the packaged skill.


Use `agent-cli` for the user's authorized Hyperliquid account operations. Obtain
command schemas with `agent-cli schema COMMAND`; arguments can be flags or
`--json '{...}'`, or a JSON object on stdin. Ordinary commands print exactly one
JSON object: `{ok:true,data,mode,paper}` or
`{ok:false,code,message,retryable,details,mode,paper}`; `mode` is `"live"` or
`"paper"` and `paper` is `true` in paper mode.
Logs/QR appear on stderr. `events --follow` and `logs` explicitly stream JSON lines.
Use `--network testnet` during testing; never silently change to mainnet.

## Paper first, then fund and go live

Start every strategy in paper mode: `agent-cli --paper ...`, `config set mode
paper`, or `run --paper`. Paper mode runs against real mainnet Hyperliquid
public market data (info + WS l2Book/trades/bbo, meta, funding) and never signs
or submits anything — no Privy session, `approveAgent`, or deposit is needed.
`order`/`cancel`/`modify`/`leverage` keep the same validation, risk limits,
builder fee and audit trail; a local simulator fills them (book-walking market
orders, resting limits, reduce-only, TP/SL, fees, funding, margin/liquidation
approximation). State is restartable under `~/.bloxwap/paper/`; `paper summary`
reports PnL/fees/funding, `paper reset --yes` clears it. Envelopes and events
carry `mode`/`paper`, paper state never mixes with live state, and going live
requires `config set mode live --yes`. Only after the paper results are proven,
continue with live onboarding below and real funding.

## Onboarding sequence

1. The user owns all settings and chooses their own Privy app or dedicated EOA
   agent; no wallet or credentials are bundled. For Privy, set `signerType` to
   `privy` and configure the app ID and `privyAppSecretRef`. For EOA, set
   `signerType` to `eoa` and configure `eoaKeyRef`, e.g. `env:BLOXWAP_EOA_KEY`
   or a mode-0600 `file:` path.
   The user creates the key and sets the secret outside the conversation on their
   own machine or runner. Never accept raw keys in CLI input or use the master EOA
   as the agent. Master-wallet approval always remains in the user's external wallet.
   The default Bloxwap builder is `0x71b09A08257078A4d642F7Dd7315e656c837329a`,
   with `f=0` (no builder fee). The default referral code is `BLOXWAP`; override
   with `config set referralCode` or `BLOXWAP_REFERRAL_CODE`. Optional non-zero
   builder fees use `config set builder.address` / `config set builder.fee` or
   `BLOXWAP_BUILDER_ADDRESS` / `BLOXWAP_BUILDER_FEE`.
2. Run `init --master-address 0x... --network testnet`. Show the returned approval
   payload/deeplink/QR. The user signs in their master wallet; submit only the
   resulting signature with `init --signature 0x...`. After agent approval, init
   applies the configured referral if the account has none and leaves existing
   referrals unchanged. Builder approval is needed only for a non-zero configured
   fee. Continue only after `approved:true`.
3. Run `fund --amount 10 --origin-chain 42161`. Show `qrAscii`/deposit address,
   origin chain/token, minimum, fees, expected received amount and expiry. On
   testnet, do not treat the default Arbitrum mainnet chain/token as a test route:
   use an explicitly supported test chain/token and `originDecimals`, or the
   credential-gated CI harness with mocked Relay and mocked Hyperliquid orders.
   If no test route is known, stop funding and report the missing route. The user
   transfers the quoted origin token. If `signatureSteps` require signatures,
   show the exact payload and submit each via `deposit` in returned order.
4. Poll `status` until each active deposit is `settled`, for at most 12 polls
   or 5 minutes, whichever comes first. Start with 1-second delays, double to a
   15-second cap, and stop with an explicit pending report if the budget expires.
   Settlement requires Relay success and a positive Hyperliquid ledger deposit
   (`userNonFundingLedgerUpdates`), not an unchanged equity balance. Stop on
   failed, refunded, expired, or abandoned deposits and explain their status.
   Quotes that never receive funds become `expired` 15 minutes after `expiresAt`.
   `deposit --abandon` marks an unfinished deposit `abandoned`. Do not place
   risk-increasing orders while a deposit is awaiting funds or pending. `cancel`
   and reduce-only orders still run.
5. Run `run --detach`, then monitor `events --follow --since SEQ`. Persist the
   last handled sequence; replay after reconnect. An unfilled or rejected order
   remains incomplete: do not claim the requested trade succeeded. A fill updates the trading
   plan, an error follows the catalog below, and expiry warnings prompt rotation
   using external master-wallet approval.

## Completion and approval boundaries

Read this skill and query schemas before acting. Keep a progress record with the
network, current stage, deposit IDs, last event sequence and order cloid/oid;
record public IDs only. Missing selected-signer settings, a wallet signature,
funding route or settled balance is a blocked stage. Report the exact next action
without requesting any secret in chat or moving to the next stage. Repeat `init`
to resume persisted approvals rather than creating another agent. Approval and
revoke payloads include `expiresAt` and are regenerated after 24 hours, or when
Hyperliquid rejects the nonce; sign the regenerated payload. An `ok:true`
transport envelope does not imply exchange acceptance. Every live or paper
`order` carries a `cloid` (generated when omitted) on the success and on the
error. A mutation timeout or disconnect is `NETWORK_ERROR` with `retryable:
false` and `details.outcome: "unknown"`. Retry that same `intentId` or `cloid`;
the CLI reuses the cloid and will not place a second order. Do not mint a new
cloid for the same intent.

For EOA rotation, the user sets a new local key and supplies only its reference
with `rotate --eoa-key-ref env:NEW_EOA_KEY`. For either signer, verify
`swapped:true` before asking the external wallet to sign old agent revocation. Require `oldRevoked:true` before claiming rotation complete.
`revoke` immediately disables local signing; only `exchangeRevoked:true` confirms
that the signed exchange revocation was submitted. Inspect `status` to verify the
agent is absent from exchange approvals. Cancel outstanding orders before final
revocation, and report any cancellation or cleanup failure explicitly.

Before an order, query `market --coin BTC` for `mid`, `szDecimals`, asset and
market leverage ceiling. Compute size/notional with decimal strings/bigints,
using the user-approved limit or the bounded IOC execution price. A valid schema
alone does not establish that an order is tradable or within the budget.

Use `--intent-id ID --intent "reason"` on trading actions to connect the user's
reasoning to the audit. The CLI binds that intent to one cloid. Risk checks use
the account leverage Hyperliquid will apply and fail closed if it cannot be
read. Live and paper mutations are serialized per account. `--live` and
`--paper` select the mode explicitly; a running runner rejects a command whose
mode does not match the runner or the saved config (`CONFIG_INVALID`) until the
runner is restarted. Trading, rotate, and revoke reject a network other than
`approvedNetwork`.
For TP/SL use `type:"tp"|"sl"` and `triggerPrice` with size/price/reduceOnly;
market orders use an explicit slippage-bounded IOC, not an unbounded market order.

## Error recovery

| Code | Action |
| --- | --- |
| RATE_LIMIT, NETWORK_ERROR | At most 3 read retries with exponential backoff. A mutation with `details.outcome` `"unknown"` is not retryable: retry the same `intentId` or `cloid` only, which the CLI reconciles. Stop if that result is still unknown |
| NONCE_COLLISION | Retry using a newly issued nonce. A stale approval nonce is not retryable; sign the regenerated payload. A lock held by a live process is `INTERNAL` and is not retryable |
| DEPOSIT_PENDING | Poll status until settled, expired, or abandoned. `cancel` and reduce-only orders still run. `deposit --abandon` stops a quote you will not fund |
| RUNNER_NOT_RUNNING | Start runner or use configured direct fallback |
| INSUFFICIENT_MARGIN | Reduce exposure or request authorized funding |
| POLICY_REJECTED | Stop and revise intent within limits; do not bypass policy |
| AGENT_EXPIRED | Rotate with master-wallet approval |
| AGENT_NOT_APPROVED | Complete init/approval or explain revocation |
| INVALID_SIZE, INVALID_PRICE | Correct input using market precision |
| UNKNOWN_MARKET | Refresh metadata; use an allowed market |
| ORDER_NOT_FOUND | Refresh orders before changing intent. An unknown or expired agent is `AGENT_NOT_APPROVED` or `AGENT_EXPIRED`, not this code |
| CONFIG_INVALID | Correct configuration/input; never insert secrets |
| UPSTREAM_ERROR, INTERNAL | Stop, inspect redacted details/logs and report failure |

## Gotchas

HyperCore perps USDC uses **8 decimals**; EVM USDC uses **6**. The quote's origin
decimals must match `originDecimals` or `fund` returns `CONFIG_INVALID`. Preserve
strings and bigints. Some deposits require **two distinct signatures**; resume
stored steps rather than restarting the route. Agent expiry is at most **180 days**.
Fills in `events.jsonl` are delivered once per exchange `tid`, including
fills that happen while the runner is down; dedupe by `tid` as well as `seq`.
Never
ask for, paste, log or import a master private key or seed. EOA agent keys are
accepted only through user-configured local references, never command input.
The agent is trade-only; local limits include markets, size/notional, leverage,
daily loss and open orders — in paper mode these limits are enforced exactly the
same way. Privy sees an L1 action hash, so it cannot independently inspect
notional/action contents; EOA agents have no remote Privy policy. Hyperliquid
agent permissions and local checks enforce those boundaries for both signers. State is always `~/.bloxwap`, env prefix `BLOXWAP_`; paper
state is `~/.bloxwap/paper/` and is never read by live commands (or vice
versa). Envelopes and events always state `mode`/`paper`.


## Verification boundaries

Offline skill tests validate the documented command examples against CLI schemas.
Mocked lifecycle tests exercise resumable approvals, pending funding, events
and failure handling. These checks do **not** prove a live agent or
exchange run. The nightly testnet lifecycle uses only a company-owned disposable
CI master account and separate test Privy app, live Privy and Hyperliquid
approvals/revocation, and explicitly mocked Relay plus mocked Hyperliquid orders
that never reach the exchange. The dedicated master account still needs a positive
test USDC balance because live approvals require prior test collateral.
The same harness supports a caller-controlled external wallet approval adapter
on a clean QA runner; its private key stays in that wallet. It never transfers
real funds. Missing CI credentials fail the job; a skipped or
mocked test must never be reported as live validation. Record the workflow run,
commit, lifecycle report, event and audit artifacts before claiming a testnet pass.
See `docs/agent-workflow.md` and `docs/testnet.md` in the repository for setup.
