The runner owns signing and nonce sequencing, subscribes to account updates,
maintains a heartbeat, and records events. State is `~/.bloxwap`; Unix IPC is
`~/.bloxwap/run.sock` (0600 inside a 0700 directory). Never expose it on a network.
Windows uses a home-derived named pipe; deployment must enforce current-user ACLs.

The CLI routes market, status, balance, positions, orders, order, cancel, modify,
leverage, rotate, and revoke through the runner. A config, network, or mode
mismatch fails with `CONFIG_INVALID`. The caller sends the resolved `mode`; the
runner also refuses when the saved config mode changes after startup. Restart
with the intended mode after changing it. The runner holds a lifetime ownership
lease. `runnerFallback:true` (default) permits direct mode only when no live or
unverified runner owner remains. A busy or unresponsive live PID blocks both
replacement and fallback; ping runs independently from queued commands.

## Wire format

Each UTF-8 line is a JSON-RPC 2.0 request or response. Requests require `id` and
`method`; `params` defaults to an object. Frames are bounded to 1 MiB and queued
serially. Admission is bounded to 128 connections, 64 queued requests and 4 MiB
of queued input. Request string IDs are limited to 128 characters. Excess work
is disconnected before admission. Send a newline after the object:

```json
{"jsonrpc":"2.0","id":1,"method":"status.get","params":{}}
```

Success returns `{"jsonrpc":"2.0","id":1,"result":...}`. Failure returns JSON-RPC
error code `-32000`, with the CLI failure envelope in `error.data`.

| Method | CLI operation |
| --- | --- |
| `market.get` | `market` |
| `status.get` | `status` |
| `balance.get` | `balance` |
| `positions.get` | `positions` |
| `orders.get` | `orders` |
| `order.place` | `order` |
| `order.cancel` | `cancel` |
| `order.modify` | `modify` |
| `leverage.set` | `leverage` |
| `config.get` | Read persisted config |
| `runner.shutdown` | Graceful shutdown |

Short command names are accepted, including `rotate` and `revoke`. The RPC config
operation is read-only. Unknown methods and unsafe inputs fail before signing.

```json
{"jsonrpc":"2.0","id":2,"method":"runner.shutdown","params":{}}
```

Large successful mutations return `{outcome:"accepted",resultPath,cloid}`;
`resultPath` points to a private local receipt containing the full response.
Orders and positions use `offset`/`limit`; request a smaller page when a read
response exceeds the frame limit.

Shutdown returns `result:{stopping:true}`, stops admission, drains accepted
commands and events, closes subscriptions/transports, and releases ownership. Client timeout or disconnect leaves mutation results uncertain:
reconcile exchange state before retrying. [Events](/docs/events) are read through
the CLI journal, not a socket streaming method.
